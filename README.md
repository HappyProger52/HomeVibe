# HomeVibe — pet-проект на Java и Spring Boot

Адаптивный сайт аренды загородных домов: каталог, личные кабинеты гостей и отдельная админ-панель. Сервер полностью перенесён на **Java 21 + Spring Boot 3.5.7**. HTML, CSS и небольшой JavaScript остались для браузерного интерфейса; Node.js для работы проекта больше не нужен.

## Быстрый запуск

Нужен **JDK 21**. Отдельная установка Maven не требуется — в проекте есть Maven Wrapper.

На этом компьютере `JAVA_HOME` уже указывает на JDK 21, хотя команда `java` из PATH запускает Java 8. Maven Wrapper использует JAVA_HOME.

В PowerShell из папки проекта:

```powershell
.\run.ps1 -AskOwnerPassword
```

Введите свой логин администратора (3–40 латинских букв, цифр, точек, _ или -) и пароль (от 12 символов, максимум 72 байта UTF-8). Ввод пароля скрыт; пароль не записывается в проект.

- Сайт: **http://127.0.0.1:3000/**
- Отдельный вход администратора: **http://127.0.0.1:3000/admin**
- Регистрация и личный кабинет гостя: **http://127.0.0.1:3000/account**

Можно передать логин сразу: `.\run.ps1 -AskOwnerPassword -AdminLogin forestadmin`. Если задаёте окружение вручную, используйте `HOMEVIBE_OWNER_LOGIN` и `HOMEVIBE_OWNER_PASSWORD`; логин по умолчанию — `owner`. Нельзя назначать администратору логин существующего клиента.

Пароль передаётся приложению через переменную окружения `HOMEVIBE_OWNER_PASSWORD`, хешируется BCrypt и хранится в памяти. При следующем запуске введите его заново. Без пароля приложение запускается, но вход владельца отключён. Сеансы завершаются после перезапуска.

Если запуск PowerShell-скрипта ограничен настройками компьютера, можно открыть проект в IntelliJ IDEA и запустить основной класс, указав пароль в переменных окружения конфигурации запуска.

### IntelliJ IDEA

1. Откройте `pom.xml` как Maven-проект.
2. Выберите JDK 21 в Project SDK и Maven Runner JRE.
3. Дождитесь загрузки Maven-зависимостей.
4. В конфигурации запуска `HomeVibeApplication` задайте `HOMEVIBE_OWNER_LOGIN` и `HOMEVIBE_OWNER_PASSWORD` своими логином и паролем. Не сохраняйте конфигурацию с паролем в Git.
5. Запустите `HomeVibeApplication.main()`.

При необходимости задайте JAVA_HOME в текущем терминале:

```powershell
$env:JAVA_HOME = 'C:\Program Files\Eclipse Adoptium\jdk-21.0.6.7-hotspot'
.\mvnw.cmd test
.\mvnw.cmd spring-boot:run
```

Первая сборка скачивает зависимости из Maven Central. Дальнейшие сборки используют локальный кеш `.maven-repository`.

## Что реализовано

- Каталог трёх домов, фильтры по гостям, датам и типу отдыха.
- Регистрация гостя по логину, имени и паролю; пароли хранятся только в виде BCrypt-хешей.
- Создание заявки после входа: имя, телефон, пожелания, даты и число гостей. Заявка привязана к аккаунту сервером.
- Личный кабинет: только свои заявки, сумма, даты и статус. Автообновление каждые 30 секунд на видимой странице и кнопка обновления.
- Расчёт суммы на сервере: цена за ночь × количество ночей.
- Минимальная аренда — одна ночь: после выбора заезда календарь выезда разрешает даты только со следующего дня. Ранее выбранный неподходящий выезд автоматически переносится; сервер также проверяет срок.
- После даты выезда владелец нажимает «Завершить проживание» у подтверждённой брони. Это окончательный статус; завершённую поездку нельзя отменить.
- Гость может оставить один отзыв с оценкой 1–5 на свою завершённую поездку. В кабинете виден статус проверки. Отменённые, ожидающие и ещё не завершённые брони не дают права на отзыв.
- В админ-панели вкладка «Отзывы» показывает очередь и число новых отзывов (обновляется каждые 30 секунд). Владелец публикует или отклоняет отзыв и может сразу добавить ответ, затем изменить ответ или снять отзыв с публикации. Уведомление находится в панели, отправки писем нет.
- Только опубликованные отзывы и ответы видны в карточках домов; средняя оценка считается только по ним. Отзывы хранятся в `data/reviews.json` (путь можно задать через `HOMEVIBE_REVIEWS_FILE`).
- Отдельный вход администратора `/admin`: список клиентов, поиск, фильтр статуса, подтверждение и отмена.
- Редактор домов: название, описание, расположение, метка, цена, вместимость, спальни и площадь.
- Загрузка обложки JPEG/PNG (до 5 МБ и 20 мегапикселей). Сервер проверяет содержимое и перекодирует картинку в PNG; файлы находятся в `data/uploads`.
- Доступность: первый заезд и последний выезд сезона, закрытые интервалы, время заезда и выезда. Правый край закрытого интервала доступен для заезда. Пустые границы сезона означают отсутствие ограничения.
- Редактирование дат или вместимости не может нарушить подтверждённую бронь. Изменение цены не меняет сумму ранее созданных заявок.
- Защита кабинета Spring Security, сессионная cookie HttpOnly, CSRF-токены и ограничение попыток входа.
- Проверка вместимости и дат, исключение пересекающихся подтверждённых броней. Смежные заезд/выезд разрешены.
- Защита от дублирования повторной отправки заявки.
- Сохранение заявок в `data/bookings.json`, клиентов в `data/customers.json`, каталога в `data/houses.json`; восстановление после перезапуска.
- Ответы об ошибках в JSON с понятными сообщениями.

## Где показаны нужные технологии

| Тема | Пример в проекте |
| --- | --- |
| ООП, инкапсуляция | `model/Booking`: приватные поля, методы `overlaps` и `withStatus`, отсутствие произвольных сеттеров |
| Интерфейсы и полиморфизм | `BookingRepository` и реализация `JsonBookingRepository` |
| Collections | `List<House>` для каталога, `LinkedHashMap<UUID, Booking>` для заявок, `HashSet` для проверки уникальности |
| Исключения | `BookingException`, `StorageException`, `try/catch` при записи файла |
| Spring Boot | `@SpringBootApplication`, встроенный сервер, `application.properties` |
| Dependency Injection | Зависимости `BookingService` передаются через конструктор; `@Service`, `@Repository`, `@Bean` |
| REST | Контроллеры с `@GetMapping`, `@PostMapping`, `@PatchMapping` |
| Валидация | DTO `CreateBookingRequest`, `@Valid`, `@NotBlank`, `@Size` |
| Обработка ошибок | `@RestControllerAdvice` и `@ExceptionHandler` |
| Тестирование | JUnit 5, Spring Boot Test, MockMvc |

Дополнительно используются `record`, `enum`, Stream API, `Optional` и Java Time. С Lombok, JPA, Docker и микросервисами пока не усложняем.

## Структура

```text
src/main/java/ru/homevibe/
  HomeVibeApplication.java   — точка входа
  model/                    — дом, заявка, статус
  dto/                      — данные запросов и ответов
  repository/               — интерфейс и файловое хранилище
  service/                  — правила бронирования и каталог
  controller/               — HTTP API и обработка ошибок
  config/                   — DI, время, вход и безопасность
src/main/resources/
  application.properties    — настройки
  static/                   — HTML, CSS, JavaScript, иллюстрация
src/test/java/ru/homevibe/   — тесты
legacy/node/                — архив предыдущего сервера, не используется
```

## Как проходит заявка

`app.js → BookingController → BookingService → BookingRepository → bookings.json`

Контроллер принимает и валидирует DTO. Сервис проверяет вместимость и даты, рассчитывает стоимость и создаёт объект `Booking`. Репозиторий сохраняет его. Spring создаёт объекты и связывает их через конструкторы — это DI.

Начните изучение с `HouseService`, затем `Booking`, `BookingRepository`, `BookingService` и `BookingController`. Конфигурацию Spring Security можно разобрать после основ.

## Проверки и сборка

```powershell
.\mvnw.cmd test
.\mvnw.cmd package
& "$env:JAVA_HOME\bin\java.exe" -jar target\homevibe-1.0.0.jar
```

Тесты проверяют стоимость, сохранение и чтение файла, повторную заявку, даты, вместимость, одновременные подтверждения, отмену, повреждённый файл, публичные страницы, защиту контактов, CSRF и полный сценарий входа владельца, изоляцию двух клиентов, обновление статуса в личном кабинете, права администратора, загрузку изображений, сохранение карточек и ограничения доступности. Они используют отдельные временные файлы и не изменяют ваши заявки.

## Учебные ограничения

Файловое хранилище рассчитано на **один запущенный экземпляр приложения**. Блокировка `synchronized` защищает проверку и сохранение внутри одного JVM; для нескольких серверов нужна транзакционная база данных. Резервируйте всю папку `data` при остановленном приложении, включая фотографии. Заменённые обложки не удаляются автоматически с диска. Файл заменяется атомарно: при ошибке записи память не обновляется. Повреждённый файл не затирается — запуск останавливается.

Это локальный pet-проект: сервер слушает 127.0.0.1. Нет оплаты, SMS, писем, восстановления пароля и подтверждения email. Для локального pet-проекта используется логин без email. Старые заявки без аккаунта остаются видны только администратору: они не привязываются по имени или телефону. В одном браузере активен один аккаунт; для параллельной проверки гостя и администратора используйте разные браузерные профили. Дома и цены демонстрационные. Для публикации нужны HTTPS, реальные материалы и правила обработки данных, резервное копирование, настройка безопасности и актуализация зависимостей. Контакты в JSON не зашифрованы; папка `data` исключена из Git.

Старая SQLite-база сохранена без изменений. Существующие заявки перенесены в JSON. Старые пароль и сеансы не переносятся — у Java-приложения собственный вход. Архив Node.js оставлен для сравнения подходов.
